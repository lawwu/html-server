Architecture · lifecycle

Five rows, four states, and a 409 for everything else

Every mutation on the artifact server goes through transition(state, event), a lookup in one small table. Any (state, event) pair not in the table is refused with a 409 that names the events that are allowed. Drive it yourself: blue arrows are the events legal from where you are now.

    The whole table

    stateevent→ next
    Illegal pairs are the point.Because the table is closed, "update a trashed page" and "purge an active page" can't happen by accident: the server answers 409 and lists what you can do.
    Visibility is not a state.Public and private are a column on the artifact, orthogonal to the lifecycle; either can be active or trashed.
    Adding a state is adding rows.An archived state would be two or three new rows. The test that walks every illegal pair covers it automatically.
    Purge is two steps on purpose.Only a trashed artifact can be purged, so deletion for good always passes through a recoverable stop. Purged rows are gone, so the name is free for a fresh create.
