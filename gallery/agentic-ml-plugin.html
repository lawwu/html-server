Claude Code plugin · Agent Skills format

An ML lifecycle where every number shows its command

Agentic ML is a set of agent skills that walk a model from “do we even need ML?” to a signed-off promotion decision through eleven gates. Each gate returns GO CONDITIONAL or NO-GO, writes a JSON artifact, and records the commands behind its headline numbers so anyone can re-run them.

claude plugin marketplace add lawwu/agentic-ml-plugin
claude plugin install agentic-ml@agentic-ml

Restart Claude Code afterwards; skills activate when relevant. Update with claude plugin marketplace update then claude plugin update agentic-ml@agentic-ml, or run /plugin.

npx skills add lawwu/agentic-ml-plugin

The skills, gate by gate

Seventeen skills on one gate line

Squares are gates, run in order by orchestrate-e2e; a NO-GO halts the run. Dots branch off a gate: optional, supporting, or informational steps. Pick any of them to see what it does, when to reach for it, and what it ships with.

Keyboard: ↑ ↓ move through the line, Home / End jump to either end.

Evaluation protocol

What makes the numbers trustworthy

Rules every skill follows, at every level. A skill that computes a metric must use the locked split and report an interval; one that reads data or runs code must record provenance.

Right kind of ML first

select-approach asks whether ML is needed at all, then picks the cheapest of rules, supervised, forecasting, unsupervised, embeddings, LLM prompting/RAG, fine-tuning, RLHF/RLVR or agents.

A locked test set

The split is made once in review-target. Test rows are read once, at promotion, after a test_keys_sha256 hash check. A second read is a high finding.

Uncertainty on every metric

95% bootstrap intervals with n, a paired comparison against the baseline, slices, calibration and an explicit operating point. “Beats the baseline” means the delta’s interval excludes zero.

Provenance

Git SHA, package versions, lockfile hashes, data hashes and seeds go into every artifact that touches data or code.

Pre-flight before compute

Loss at init, overfit one batch, save/resume, and a too-good-to-be-true check run before training spends budget.

Deployment readiness

Training/serving parity in a fresh process, latency and memory budgets, a data contract and drift baseline, plus monitoring and rollback plans.

ML Test Score

Each run is scored against Google’s 28-test production-readiness rubric. The final score is the lowest of its four sections.

One shared vocabulary

Decisions are GO / NO-GO / CONDITIONAL; severities are blocker / high / medium / low. Every skill writes <skill>.json on a common base schema.

How it adapts to you

Three levels, one quality bar

Pass --level or save it once in .claude/agentic-ml.local.md. Level changes how much the agent explains and how often it stops for you.

Never changes with level: the checks, the thresholds, the locked test set, or what needs your approval. Promotion always requires human sign-off.

Demo scenarios and benchmark-e2e

Datasets built to hide the usual mistakes

The repo ships generators, not data. easy (premium upgrade, 1,200 rows, clean, no leakage) and medium (telecom churn with a vague goal and a subtle temporal leak) are for trying the plugin. The three hard ones are what benchmark-e2e runs no-plugin, plugin and AutoGluon AutoML against.
