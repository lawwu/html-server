Claude Code · settings precedence

Claude Code settings — which file wins?

Claude Code reads settings from up to five levels, from your organization's managed policy down to your own ~/.claude/settings.json. When two of them set the same key, the higher one wins. Permission rules don't fight that way: every level's allow, ask and deny rules are pooled, then checked deny first.

Run /status and Claude Code lists the files it loaded, not which one supplied each key. The tool below does that part, for a made-up repo called ledgerline-api.

How the stack resolves

Claude Code reads your user, project and local files, your organization's managed settings and anything you pass with --settings, and uses the value from the highest level that sets a key: managed, then command line, project local, shared project, user. Managed settings arrive as a managed-settings.json file (on macOS in /Library/Application Support/ClaudeCode/), an MDM policy, or server-managed settings from the claude.ai admin console.

Single values

model holds one value, so the highest file that sets it wins outright. /model saves your pick to ~/.claude/settings.json, the lowest file, so a model in project, local or managed settings, or one passed with --settings, outranks it again at the next launch.

env, one variable at a time

An env block follows the same levels per variable, and a file's value replaces the same variable exported in your shell, except when the Claude Desktop app or a self-hosted runner builds the launch environment. Project and local files can't set some variables at all, such as CLAUDE_CONFIG_DIR and telemetry switches like CLAUDE_CODE_ENABLE_TELEMETRY.

Lists merge

When several files set a list such as permissions.allow, Claude Code combines them, so each file adds entries without removing another file's. Four model keys follow their own rules: fallbackModel, modelPicker, availableModels and modelSettings.

How permission rules combine

  1. Pool. Allow, ask and deny rules from every level are combined, unless managed settings set allowManagedPermissionRulesOnly. Then only managed rules count, and --allowedTools is ignored too.
  2. Wait for trust. allow rules in a committed .claude/settings.json apply only after you accept the workspace trust dialog. Its deny and ask rules apply right away, since they only restrict.
  3. Check deny, then ask, then allow. The first match decides, and specificity doesn't change the order: Bash(aws *) in deny blocks aws s3 ls even when Bash(aws s3 ls) is allowed. A user-level deny blocks a project-level allow, and the reverse.
  4. Fall back to the mode. With no match, the permission mode decides. In Manual mode, edits and Bash commands outside a built-in read-only set ask first; reads inside the working directory don't.

--allowedTools and --disallowedTools add allow and deny rules for one session, and a deny in any settings file still blocks a tool --allowedTools names.

Outside the stack

Environment variables and flags such as --model aren't levels; each one pairs with a key by its own rule. For the model, --model beats ANTHROPIC_MODEL, both beat model in any file, managed included, and ANTHROPIC_DEFAULT_MODEL applies only when nothing else selects a model.

A managed model is a starting default, not a lock. The locks are availableModels and deniedModels, and --model picks only from the models your organization allows.

Surprises worth knowing

  • “Yes, and don't ask again” saves an allow rule to .claude/settings.local.json. It can't outrank an ask rule from a project or managed file, so the prompt keeps coming.
  • permissions.defaultMode set to auto or bypassPermissions doesn't take effect from project or local settings.
  • In user settings, Read(/secrets/**) anchors at ~/.claude/, not your project. Use a ~/ or // path there.
  • A few security keys keep a stricter value from a lower level even against managed settings, such as disableClaudeAiConnectors: true from any scope.
  • Settings files are strict JSON: a // comment or a trailing comma is a Settings Error. /status lists the files that loaded, and claude doctor lists entries Claude Code rejected.
